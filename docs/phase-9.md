# 阶段九：工具执行过程展示

## 本阶段完成内容

在聊天页面中完整展示 Agent Loop 的工具执行过程：工具调用开始时在当前回复区域插入过程卡片，结束时更新状态与耗时；正文与卡片按实际事件顺序交错展示。目标是让普通用户看懂 Agent 做了什么，同时不泄露敏感信息、不在聊天里直接渲染大段原始数据。本阶段不改数据库结构（无新迁移），不改 Agent Runtime 的执行语义。

### 后端

- 工具事件补充展示字段（`app/services/agent_runtime.py`）：
  - `tool_call_start` 新增 `arguments`（整理后的输入参数）与 `serverName`（MCP Server 名称，非 MCP 工具为 null）。参数在发送前脱敏（API Key 与 MCP 环境变量值替换为 `***`），单个字符串值超过 500 字符截断并标注原始长度，集合限 50 项、嵌套限 6 层，防止大参数撑爆事件。参数不是合法 JSON 时为 null。
  - `tool_call_end` 新增 `result`：`{text, truncated, totalLength}` 整理后的结果文本——内置工具成功时为结果 JSON（缩进格式）；MCP 成功时为结果文本（二进制内容只保留"类型 + 大小"占位，不携带 Base64）；失败时为可读原因与参数提示（不含程序异常堆栈）；超过 4000 字符截断并标注原始长度。`_ToolOutcome` 相应增加 display 字段，与给模型的完整结果（context_text）分离。
  - `tool_call_end` 的 `status` 增加 `cancelled`：工具执行中被取消时，Runtime 在取消路径上给在执行的卡片补发一个 cancelled 终态（`result` 为 null），卡片不会停留在"正在执行"。
  - MCP 工具的展示名改为纯工具名，Server 名称经 `serverName` 单独下发；聊天层拼出"Server·工具"用于"正在调用工具"提示。
- 展示时间线与快照恢复（`app/services/chat_generation.py`、`app/api/routes/chat.py`、`app/schemas/chat.py`）：
  - `GenerationRun` 维护 `timeline`：正文段（连续增量合并）与工具卡片段（callId 配对、原地更新状态/耗时/摘要/结果）按事件顺序交错。
  - SSE 快照（`snapshot`）与 `GET /messages` 的生成快照都携带 `timeline`，断线重连或重新打开生成中的会话时恢复卡片、状态与顺序，而不是只剩一段正文。
- MCP 客户端（`app/services/mcp_client.py`）：非文本内容项的占位提示补充大小信息（约 N 字符 Base64 数据），正文与 Base64 都不进入结果。
- 日志与事件摘要维持脱敏；完整工具结果与 Skill 指令正文仍然只进入模型上下文，不写入日志或展示事件。

### 前端

- `api/chat.ts`：事件类型扩展 `serverName` / `arguments` / `result` / `cancelled`，新增 `ToolResultPayload`、`ToolEndStatus`、`GenerationTimelineItem`；`ChatGeneration` 与 snapshot 增加 `timeline`。
- `stores/chat.ts`：生成状态从"正文 + 工具轨迹列表"改造为段落化时间线 `segments`（正文段 / 工具卡片段按事件顺序交错）：
  - `text_delta` 追加到上一段正文或新起一段；`tool_call_start` 追加卡片；`tool_call_end` 按 callId 配对、原地更新（优先仍在执行的卡片），完成顺序不改变卡片位置；同一个工具多次调用时每次独立展示。
  - 事件按运行标识校验（`runId`）：旧运行的迟到事件不落入当前时间线。
  - 运行收尾（`settleGeneration`）：仍在执行的卡片标记"已取消"（run_end/停止生成）或"状态未知"（错误/连接中断），不停留在"正在执行"也不误标成功；时间线挂到已保存消息 id（`toolTimelines`），无保存消息时以孤儿卡片留在会话末尾（`orphanTools`，下次发送时清理）。两者只在页面内存保留，刷新后不恢复（持久化留到运行记录阶段；**阶段十三已改为轨迹随消息入库，见 `phase-13.md`**：`chat_messages.timeline_json`，刷新后由 `seedTimelines` 恢复，仅无保存消息的孤儿卡片仍只在内存中）。
  - 断线自愈：重连成功由快照（含时间线）恢复；重连失败或后端不可达时卡片标记"状态未知"并保留，正文进入错误提示。
- `components/ToolCallCard.vue`（新增）：过程卡片。收起时显示工具名、类型徽标（内置工具 / MCP / Skill）、状态图标 + 文字（执行中 / 完成 / 失败 / 已取消 / 状态未知，不只靠颜色区分）与耗时、摘要；展开后显示整理后的输入参数（键值分行，字符串保留换行，其余 JSON 缩进）与执行结果（JSON 重新缩进；超过 1200 字符默认只展示前段并标注"已截断"提供"展开全部"；后端截断时标注原始长度）；取消/未知状态明确提示没有结果。工具返回内容全部按纯文本渲染（文本插值，不拼 HTML、不执行脚本）。
- `views/chat-format.ts`（新增）：参数/结果格式化与截断的纯逻辑，便于单测。
- `views/ChatView.vue`：
  - 生成气泡与已保存消息都按时间线交错渲染正文与卡片（工具调用前的文字在卡片上方，之后的文字接在下方）；无保存消息的收尾运行在消息之后渲染孤儿卡片。
  - 滚动：保持原有底部跟随（60px 阈值）；用户上翻即暂停跟随、不强行拉回；出现"回到最新消息"悬浮按钮，点击回到底部并恢复跟随；切换会话时按跟随状态重置滚动。
  - 展开/收起卡片时补偿滚动高度差，尽量保持当前阅读位置（仅当卡片位于可视区域底部以上时补偿）。

## 验证方式

```bash
# 1. 后端
cd backend
uv sync
uv run pytest

# 2. 前端（另开终端）
cd frontend
npm install
npm run type-check && npm run test && npm run build
npm run dev
```

1. 过程卡片：给 Agent 绑定"当前时间"后提问"现在几点"——先出现"执行中"卡片（带参数可展开），完成后变为"完成 · 耗时"；卡片上方的引导文字保留，工具之后的结论文字接在卡片下方。
2. 展开与截断：让 Agent 执行 shell 命令（输出较长）或读取较大文件——展开卡片可见缩进的参数与结果；超长结果先展示前段并标注"已截断"，点"展开全部"后显示完整（后端上限 4000 字符，超出标注原始长度）。
3. 失败原因：让模型调用一个不存在的工具名、或用非法时区调用"当前时间"——卡片标"失败"，展开后是可读原因与参数提示，没有异常堆栈。
4. 取消：工具执行中点"停止生成"——未完成卡片标"已取消"，不会停留在"正在执行"；部分正文保存为未完成，卡片挂在未完成消息上。
5. 断连：生成中用开发者工具断开网络（或停掉后端再恢复）——重连成功由快照恢复卡片与顺序；连续失败后卡片标"状态未知"，正文进入错误提示。
6. 状态保留：一次带工具调用的回复完成后切换到别的会话再切回——消息内的工具卡片、执行状态与交错顺序保持不变；刷新页面后卡片消失（预期，持久化留到运行记录阶段）。
7. MCP：绑定一个 MCP Server 并提问触发其工具——卡片标题为"Server 名称 · 工具名"，类型徽标为 MCP；含二进制内容的 MCP 结果只显示类型与大小提示。
8. 滚动交互：生成中向上翻阅历史——新内容不再把视图拉回底部，出现"回到最新消息"按钮；点击或手动回到底部后恢复跟随；展开/收起卡片时阅读位置不跳动。
9. 回归：纯对话（无工具）流程与阶段七/八一致；后端 pytest 与前端 type-check/test/build 全部通过。
