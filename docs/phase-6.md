# 阶段六：Agent 管理

## 本阶段完成内容

在已有骨架上实现"Agent 管理"模块。Agent 把模型、系统提示词、工具、Skills 与 MCP Server 组合成面向具体任务的配置。本阶段只实现配置管理与页面状态；Agent Loop、运行记录和历史会话不在本阶段范围内。

### 后端

- 业务表（Alembic 迁移 `0006`）：
  - `agents`：名称、说明、系统提示词正文、提示词版本号（从 1 开始）、引用的模型（`model_id` 外键）、最大执行轮数（1–100，默认 25）、是否默认 Agent。
  - `agent_bindings`：能力绑定行（`agent_id` + `capability_type` + `ref_key`，唯一约束），随 Agent 删除级联清理。`ref_key` 按类型取稳定标识：工具存 `tools.key`（执行层按 key 绑定实现）、Skill 存 `dir_name`（目录删除重建后行 id 会变，目录名才是稳定标识）、MCP Server 存十进制 id 字符串（被引用的 Server 删除被阻止，id 在引用期间稳定）。
- 系统提示词版本：首次保存生成版本 1；仅当提示词内容变化时递增版本号，修改名称、模型或能力绑定不影响版本号。本阶段只保存当前内容与版本号，版本历史与比较/恢复属于后续阶段。
- 接口（`app/api/routes/agents.py`，前缀 `/api/agents`）：
  - `GET ""` 列表（默认 Agent 置顶，其余按最近更新倒序）；`GET /{id}` 详情（含系统提示词与逐条绑定信息）；`POST ""` 新增（201）；`PUT /{id}` 全量编辑；`DELETE /{id}` 删除；`PUT /{id}/default` 设为默认。
  - 校验：名称必填；必须选择已存在的模型；最大执行轮数必须为 1–100 的正整数；失败返回 422 与 `{"message", "fields"}` 字段级原因。说明与系统提示词可选。
  - 能力绑定规则：只有启用的工具、Skills 和 MCP Server 可以**新增**到配置；已绑定的能力后来被停用时保留原绑定，编辑页可手动移除，也可保留后保存其他修改（后端按"请求中的绑定若已存在于该 Agent 则允许"实现）。绑定不存在或不启用的资源返回 422 并说明原因。
  - 默认一致性：保存第一个 Agent（或当前无默认）时自动设为默认；设为默认在同一事务内取消旧默认；删除默认 Agent 且还有其他 Agent 时要求 `new_default_id`（409），切换与删除同事务提交；删除最后一个 Agent 允许确认后删除。本阶段没有历史会话，不加会话引用限制。
  - 详情响应中每条绑定都解析为当前状态（名称、说明、启用状态、是否可用）：资源已停用时 `available=false` 且名称照常返回；资源已不存在（如 Skill 目录被手动删除后扫描清理）时保留绑定并展示为失效项，绑定数量按实际保存的绑定统计，包含已停用与已失效的能力。
- 资源引用保护（引用检查一律在后端执行，`app/services/agent_refs.py` 供三个管理路由共用）：
  - 被任意 Agent 引用的模型、Skill 或 MCP Server 删除时返回 409，提示中列出正在使用它的 Agent 名称；用户需先在对应 Agent 中移除绑定、更换模型，或删除相关 Agent。不得自动解除绑定或替换模型；内置工具继续保持不可删除。
  - 删除默认模型时先检查 Agent 引用，再执行模型管理已有的默认项切换规则。
- 运行时过滤停用能力的逻辑属于 Agent Loop 阶段，本阶段只处理配置与可用状态展示。

### 前端

- `views/AgentsView.vue`：Agent 表格（名称与默认徽章、说明、模型名称与标识、工具 / Skills / MCP Server 绑定数量、最后更新、操作），空状态与新建入口；删除确认对话框与"删除默认 Agent 需先选择新默认"的交互与模型管理一致。
- `components/AgentFormDialog.vue`：新建/编辑表单。
  - 名称、说明、系统提示词（多行文本域，适合长内容；编辑时展示"当前版本 vN"）。
  - 模型下拉展示名称与模型标识；新建时默认选中当前默认模型；没有可用模型时在表单内提示先添加模型并提供"前往模型管理"入口。
  - 最大执行轮数：默认 25，说明范围 1–100 及用途（限制后续 Agent Loop 的执行轮数，本阶段仅保存配置）。
  - 工具 / Skills / MCP Server 多选（可全不选），每个选项展示名称与用途说明；已停用选项不可新增（复选框禁用），已绑定后被停用的选项保留勾选并标记"已停用，不可用"，可取消勾选移除；资源已失效的绑定同样保留展示并允许移除。
- `views/agent-form.ts`：表单校验、载荷构造与失效绑定识别的纯函数；`api/agents.ts`、`stores/agents.ts` 接口与状态。
- 页面配色、字号、布局与既有管理页面一致（`variables.css` 变量、卡片表格、对话框交互）。

## 验证方式

```bash
# 1. 后端
cd backend
uv sync
uv run alembic upgrade head        # 应用 0006 迁移
uv run pytest

# 2. 前端（另开终端）
cd frontend
npm install
npm run type-check && npm run test && npm run build
npm run dev
```

打开 http://localhost:5173/#/agents （侧边栏"Agent 管理"）：

1. 空状态显示新建入口；新建时若尚未配置任何模型，表单内提示"前往模型管理"。
2. 保存第一个 Agent 后自动带"默认"徽标；再建一个不自动变默认，用"设为默认"切换。
3. 编辑提示词内容并保存，再次编辑时"当前版本"递增；只改名称、模型或绑定则版本号不变。
4. 在工具 / Skills / MCP 管理中停用某能力后打开引用它的 Agent：该选项保留勾选并显示"已停用，不可用"，可保留保存其他修改，也可取消勾选移除；列表绑定数量包含已停用项。
5. 删除被 Agent 引用的模型 / Skill / MCP Server 会被拒绝，提示中列出使用它的 Agent 名称；移除绑定后可正常删除。
6. 删除默认 Agent 且还有其他 Agent 时，必须先选择新默认项；删除最后一个 Agent 后页面回到空状态。刷新页面、重启后端后配置、默认状态与版本号均保留。
